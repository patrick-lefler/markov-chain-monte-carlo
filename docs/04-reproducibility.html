Reproducibility

How to rerun the analysis and where the results can mislead

Every number on this site is computed from one synthetic data file, data/synthetic_returns.csv, which R/generate_data.R generates from a fixed seed. Every Markov chain is run with an explicit seed. Nothing is downloaded during a render, so rendering the same commit with the same package versions gives the same results. This page explains how to rebuild the site, records the environment it was built in, and states where the results can mislead.

Quick start

The code and data are in the GitHub repository patrick-lefler/markov-chain-monte-carlo. To rebuild everything from a clean copy:

git clone https://github.com/patrick-lefler/markov-chain-monte-carlo
cd markov-chain-monte-carlo
Rscript -e 'renv::restore()'   # once: install the package versions pinned in renv.lock
quarto render

The rendered site is written to docs/. The data file is committed, so quarto render does not need to regenerate it (see Data).

Every random stream is seeded explicitly. run_metropolis() calls set.seed(seed) before each chain, and the seeds are:

  • 42 for chain 1 of the 10-factor analysis (R/analysis.R), and 42 for the 2D hero chain on the home page (index.qmd).
  • 101 for the three step-size chains on The Metropolis Engine page.
  • 99, 123, 456 for chains 2–4 of the 10-factor analysis.
  • 2026 (in run_analysis()) for the random signs of the “mixed” starting point.

Because each chain resets the seed, results do not depend on the order in which pages are rendered.

Caching

  • Quarto freeze (_freeze/). _quarto.yml sets freeze: auto, so a full quarto render re-executes a page only when that page’s .qmd file changes. Edits to the R/ scripts do not count as a change. After editing a script, render each page explicitly (for example quarto render 03-diagnostics.qmd), because Quarto always executes a page that is rendered on its own. _freeze/ is committed to git, so a fresh clone renders from the stored results until a page changes.

Known limitations

Limits of reproducibility

  • Bit-for-bit equality is expected only on the same platform and package versions. Floating-point and BLAS differences across machines can change low-order digits.
  • MASS::mvrnorm() uses an eigendecomposition of the covariance matrix, which can differ slightly across BLAS/LAPACK libraries. Rerunning R/generate_data.R on another platform may therefore produce a slightly different data file. The committed file and its checksum above are the reference.
  • The Metropolis chains are sensitive to every random draw. A tiny numerical difference in the data or the log-posterior can change an accept/reject decision, after which the chain follows a different path. The headline values (acceptance rate, split-\(\hat{R}\), ESS, credible-interval widths) would then differ in their later digits, though not in their conclusions.
  • Quarto versions affect rendering, not the numbers.

Model limitations

The Scope & Limitations callout on the home page summarizes these for a first-time reader. In full:

  1. Synthetic data. All results use a 250-day sample from a known multivariate normal distribution. Real returns show regime shifts, volatility clustering and structural breaks that this data set does not.
  2. Covariance is fixed. \(\mathbf{\Sigma}\) is set to its sample estimate, so only uncertainty in the mean vector is modeled. Covariance uncertainty, usually the larger driver of VaR error, is excluded, so the reported credible intervals are lower bounds on total parameter risk.
  3. Gaussian tails. The normal likelihood cannot represent fat tails or skew. VaR and ES here are parametric Gaussian measures and will understate losses in stressed markets.
  4. The sampler has not converged. All ten factors are at or above the split-\(\hat{R}\) threshold of 1.01, pooled bulk ESS is well below 400, and the MCMC VaR credible interval is narrower than the exact one. See Audit & Diagnostics.
  5. Short run and burn-in. The chains run 3,000 iterations with a 500-draw burn-in, which the trace plots show is insufficient for overdispersed starts.
  6. Deliberately simple setting. The model is conjugate, so MCMC is not needed here; it is used so that every result can be checked against an exact answer. Performance on non-conjugate models is untested.
  7. Narrow portfolio specification. Results cover one equal-weighted portfolio at a 1-day horizon and a 95% confidence level.
  8. Illustrative scaling figures. The grid-versus-MCMC timings in the Dimensional Complexity table are illustrative estimates, not measured benchmarks.

What would change the conclusions

Change Likely effect
Longer chains, or a covariance-preconditioned or gradient-based sampler (HMC/NUTS) Split-\(\hat{R}\) and ESS would likely meet their thresholds, and the MCMC credible intervals would move toward the exact ones. The “sampler understates risk” finding is specific to this isotropic sampler.
Treating the covariance as uncertain Wider VaR and ES credible intervals, since covariance uncertainty adds to the mean uncertainty modeled here.
Fat-tailed likelihood (for example Student-t) Higher VaR and ES, and a non-conjugate posterior with no exact benchmark.
A different generator seed or sample length Different sample means (the Portfolio Risk page shows that the Tech Growth sample drift sits well below its true value by chance), and so different posterior centers.

What real data would replace each assumption

Assumption Real-data replacement
Synthetic multivariate normal returns Daily total returns for the portfolio’s actual factor exposures or index proxies
Equal weights The portfolio’s actual position weights
Fixed sample covariance A covariance estimated jointly with the means, or a shrinkage or factor-model estimate with its own uncertainty
Known true parameters None: with real data the truth is unknown, so the exact-posterior benchmark is only available for conjugate models like this one

How to use these results. Use them to learn how Random-Walk Metropolis works, why a healthy acceptance rate is not evidence of convergence, and how to audit a sampler with multi-chain diagnostics and an exact benchmark. Do not use the VaR and ES figures, or the sampler as configured, for risk decisions on a real portfolio.

Because each chain resets the seed, results do not depend on the order in which pages are rendered.

## Caching {#caching}

-   **Quarto freeze (`_freeze/`).** `_quarto.yml` sets `freeze: auto`, so a full `quarto render` re-executes a page only when that page's `.qmd` file changes. Edits to the `R/` scripts do not count as a change. After editing a script, render each page explicitly (for example `quarto render 03-diagnostics.qmd`), because Quarto always executes a page that is rendered on its own. `_freeze/` is committed to git, so a fresh clone renders from the stored results until a page changes.

## Known limitations {#limitations}

### Limits of reproducibility {#repro-limits}

-   Bit-for-bit equality is expected only on the same platform and package versions. Floating-point and BLAS differences across machines can change low-order digits.
-   `MASS::mvrnorm()` uses an eigendecomposition of the covariance matrix, which can differ slightly across BLAS/LAPACK libraries. Rerunning `R/generate_data.R` on another platform may therefore produce a slightly different data file. The committed file and its checksum above are the reference.
-   The Metropolis chains are sensitive to every random draw. A tiny numerical difference in the data or the log-posterior can change an accept/reject decision, after which the chain follows a different path. The headline values (acceptance rate, split-$\hat{R}$, ESS, credible-interval widths) would then differ in their later digits, though not in their conclusions.
-   Quarto versions affect rendering, not the numbers.

### Model limitations {#sec-limitations}

The [Scope & Limitations](index.qmd) callout on the home page summarizes these for a first-time reader. In full:

1.  **Synthetic data.** All results use a 250-day sample from a known multivariate normal distribution. Real returns show regime shifts, volatility clustering and structural breaks that this data set does not.
2.  **Covariance is fixed.** $\mathbf{\Sigma}$ is set to its sample estimate, so only uncertainty in the mean vector is modeled. Covariance uncertainty, usually the larger driver of VaR error, is excluded, so the reported credible intervals are lower bounds on total parameter risk.
3.  **Gaussian tails.** The normal likelihood cannot represent fat tails or skew. VaR and ES here are parametric Gaussian measures and will understate losses in stressed markets.
4.  **The sampler has not converged.** All ten factors are at or above the split-$\hat{R}$ threshold of 1.01, pooled bulk ESS is well below 400, and the MCMC VaR credible interval is narrower than the exact one. See [Audit & Diagnostics](03-diagnostics.qmd).
5.  **Short run and burn-in.** The chains run 3,000 iterations with a 500-draw burn-in, which the trace plots show is insufficient for overdispersed starts.
6.  **Deliberately simple setting.** The model is conjugate, so MCMC is not needed here; it is used so that every result can be checked against an exact answer. Performance on non-conjugate models is untested.
7.  **Narrow portfolio specification.** Results cover one equal-weighted portfolio at a 1-day horizon and a 95% confidence level.
8.  **Illustrative scaling figures.** The grid-versus-MCMC timings in the Dimensional Complexity table are illustrative estimates, not measured benchmarks.

**What would change the conclusions**

| Change | Likely effect |
|:-------------------------------|:-----------------------------------------------|
| Longer chains, or a covariance-preconditioned or gradient-based sampler (HMC/NUTS) | Split-$\hat{R}$ and ESS would likely meet their thresholds, and the MCMC credible intervals would move toward the exact ones. The "sampler understates risk" finding is specific to this isotropic sampler. |
| Treating the covariance as uncertain | Wider VaR and ES credible intervals, since covariance uncertainty adds to the mean uncertainty modeled here. |
| Fat-tailed likelihood (for example Student-t) | Higher VaR and ES, and a non-conjugate posterior with no exact benchmark. |
| A different generator seed or sample length | Different sample means (the Portfolio Risk page shows that the Tech Growth sample drift sits well below its true value by chance), and so different posterior centers. |

**What real data would replace each assumption**

| Assumption | Real-data replacement |
|:-------------------------------|:-----------------------------------------------|
| Synthetic multivariate normal returns | Daily total returns for the portfolio's actual factor exposures or index proxies |
| Equal weights | The portfolio's actual position weights |
| Fixed sample covariance | A covariance estimated jointly with the means, or a shrinkage or factor-model estimate with its own uncertainty |
| Known true parameters | None: with real data the truth is unknown, so the exact-posterior benchmark is only available for conjugate models like this one |

**How to use these results.** Use them to learn how Random-Walk Metropolis works, why a healthy acceptance rate is not evidence of convergence, and how to audit a sampler with multi-chain diagnostics and an exact benchmark. Do not use the VaR and ES figures, or the sampler as configured, for risk decisions on a real portfolio.
